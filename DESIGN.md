# DESIGN.md

В данном документе описана архитектура, алгоритмическая сложность и примененные принципы чистого кода для модуля логики игры «Быки и коровы».

---

## Структуры данных и алгоритмы

### Структуры данных

- **`CacheInterface` (Объект-кэш):** Для функции `countPossibleSecrets` используется гибридный объект-функция со свойством `cache` типа `Record<string, number>`. Выбор хэш-таблицы (Key-Value) обоснован необходимостью получения сохраненных результатов за константное время $O(1)$ для оптимизации повторяющихся вычислений комбинаторики.
- **`Set` (Множество):**
  - В `evaluateGuess` структура `Set` инициализируется напрямую из строки `secret` (без предварительного разбиения на массив, так как строка является итерируемым объектом). Множество обеспечивает мгновенный поиск символов за $O(1)$.
  - В `generateSecret` и `isValidGuess` используется для эффективной фильтрации уникальных символов и проверки их количества за $O(N)$.
- **Массивы (`Array`):** Используются для применения декларативных методов высшего порядка (`reduce`, `filter`, `every`), сохраняя иммутабельность данных и функциональный стиль.

### Алгоритмы

#### Алгоритм `evaluateGuess` (Оценка попытки)

**Суть алгоритма:** Функция оценивает сходство между секретным словом `secret` и догадкой `guess`.

1. Строка `secret` преобразуется в `Set` для ускорения поиска.
2. Метод `reduce()` итерируется по каждому символу массива, полученного из строки `guess`.
3. Для текущего символа и его индекса проверяется строгое равенство `char === secret[i]` (**Бык**).
4. Если символ не совпал по позиции, но присутствует в множестве `secretSet.has(char)`, то это **Корова**. В отличие от линейного поиска `.includes()`, метод `.has()` выполняется за константное время.
5. Результаты аккумулируются в объект `{ bulls, cows }`.

#### Алгоритм `countPossibleSecrets` (Расчет возможных секретов)

**Суть алгоритма:** Функция вычисляет количество возможных комбинаций секретных слов заданной длины на основе выбранного алфавита.

1. Использует **мемоизацию**: перед расчетами проверяется наличие ключа `${length}-${base}` в объекте `cache`. Если значение есть, оно возвращается сразу.
2. Алгоритм реализован через **хвостовую рекурсию**, где на каждом шаге `length` уменьшается на 1, а накопленное количество `newCount` умножается на число оставшихся доступных символов в алфавите (`ALPHABETS[base].length - newLength`).

#### Алгоритм `generateSecret` (Генерация секретного числа)

**Суть алгоритма:** Функция формирует строку уникальных символов заданной длины в выбранной системе счисления.

1. **Валидация параметров:** Проверяется, что `length` находится в допустимых границах (`MIN_SECRET_LENGTH..MAX_SECRET_LENGTH`) и не превышает `BINARY_MAX_LENGTH` для двоичной системы. При нарушении выбрасывается `RangeError`.
2. **Частный случай для `Base.bin`:** Для двоичной системы результат возвращается сразу на основе случайного числа (`seed < 0.5 ? '01' : '10'`).
3. **Преобразование случайного числа:** Случайное число `seed` переводится в строку в целевой системе счисления через `.toString(ALPHABETS[base].length)`, отбрасывается префикс `'0.'`, и строка обрезается до нужной длины `length`.
4. **Быстрая проверка:** Если полученная строка уже прошла `isValidGuess` (все символы уникальны и корректны), она возвращается сразу.
5. **Устранение коллизий и добивка длины:** Повторяющиеся символы отфильтровываются через `Set`. Из свободных символов алфавита (`freeAlphabet`) в цикле `while` добираются недостающие знаки через `.pop()`, пока длина строки не достигнет `length`.

#### Алгоритм `createDigitValidator` (Фабрика валидатора символов)

**Суть алгоритма:** Функция высшего порядка, создающая замыкание для проверки принадлежности одного символа алфавиту конкретной системы счисления.

1. Принимает параметр `base: Base` и возвращает функцию-предикат `(char: string) => boolean`.
2. При вызове проверяет, что входной символ не является пустой строкой.
3. Приводит символ к нижнему регистру (`toLowerCase()`) и проверяет его наличие в строке `ALPHABETS[base]` с помощью метода `.includes()`.

#### Алгоритм `isValidGuess` (Валидация попытки игрока)

**Суть алгоритма:** Функция проверяет корректность введенной строки перед её оценкой по принципу «быстрого отказа» (Fail-Fast).

1. Создается предикат `isValidChar` через вызов `createDigitValidator(base)`.
2. **Проверка границ длины:** Проверяется попадание `guess.length` в диапазон `[MIN_SECRET_LENGTH, MAX_SECRET_LENGTH]`, а для `Base.bin` — ограничение `BINARY_MAX_LENGTH`.
3. **Проверка уникальности символов:** Строка приводится к нижнему регистру и помещается в `Set`. Если `size` множества не равен целевой длине `length` (присутствуют дубликаты или длина не совпадает с заданной), возвращается `false`.
4. **Проверка алфавита:** Строка разбивается на массив символов, и метод `.every()` проверяет допустимость каждого символа через `isValidChar`.

## Сложность алгоритмов (Big O)

Для анализа обозначим:

- $N$ — длина загаданного слова/попытки (`length`), где $2 \le N \le 6$.
- $A$ — длина алфавита (`ALPHABETS[base].length`), фиксированная для каждого `Base`.

| Функция                    | Временная сложность (Time)                     | Пространственная сложность (Space)   | Обоснование                                                                                                                                                                                                                                                                                                                                                                                                              |
| :------------------------- | :--------------------------------------------- | :----------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`generateSecret`**       | $O(A)$                                         | $O(A)$                               | **Time:** Генерация строки из случайного числа зависит от размера алфавита. Фильтрация `freeAlphabet` также проходит по всему алфавиту за $O(A)$.<br>**Space:** Создание массива оставшегося алфавита занимает место, пропорциональное размеру алфавита $O(A)$.                                                                                                                                                          |
| **`evaluateGuess`**        | $O(N)$                                         | $O(N)$                               | **Time:** Создание множества `Set` из строки занимает $O(N)$. Метод `reduce` обходит строку `guess` за $O(N)$ шагов. Внутри каждого шага операция `secretSet.has(char)` выполняется за константное время $O(1)$. Итоговая сложность снижена до линейной: $O(N + N) = O(N)$.<br>**Space:** Выделяется память под `Set` размера $N$ и массив символов после `split('')`.                                                   |
| **`isValidGuess`**         | $O(N)$ (в лучшем) / $O(N \times A)$ (в худшем) | $O(N)$                               | **Time:** Создание `Set` занимает $O(N)$. Использование метода `every()` обеспечивает оптимизацию «до первой лжи»: перебор массива прекращается сразу же при обнаружении невалидного символа. В худшем случае (все символы валидны) метод `every` сделает $N$ итераций с поиском по алфавиту `.includes()` за $O(A)$, что дает $O(N \times A)$.<br>**Space:** Выделяется память под `Set` размера $N$ и массив символов. |
| **`countPossibleSecrets`** | $O(N)$ (без кэша) / $O(1)$ (с кэшем)           | $O(N)$ (без кэша) / $O(1)$ (с кэшем) | **Time:** Без кэша рекурсия выполняется ровно $N$ раз. С кэшем — мгновенное чтение за $O(1)$.<br>**Space:** Глубина стека вызовов при рекурсии равна $N$. При попадании в кэш стек не растет.                                                                                                                                                                                                                            |

## Управление состоянием и схема `localStorage`

### Модели данных (`GameState`, `History`, `WinRecord`)

Состояние приложения инкапсулировано в замыкании (`createGameStore`) и обновляется **строго иммутабельно** (каждое изменение порождает новый объект состояния и новый массив записей без мутации исходных ссылок).

- **`GameState` (Состояние игры):** Единый объект, описывающий текущую сессию:
  - `status: 'idle' | 'playing' | 'won'` — текущий этап жизненного цикла игры.
  - `currentBase: Base` — выбранная система счисления (`bin`, `oct`, `dec`, `hex`).
  - `currentLength: number` — выбранная длина секретного слова.
  - `currentSecret: string` — загаданная комбинация символов.
  - `currentLog: readonly History[]` — иммутабельный массив попыток текущей игры (обновляется через `[...state.currentLog, entry]`).
  - `winRecords: readonly WinRecord[]` — загруженная история побед для таблицы рекордов.
- - **`History` (Запись попытки):** Структура одного хода игрока в логе текущей игры:
  - `guess: string` — введенная пользователем комбинация.
  - `evaluare: Evaluare` — вложенный объект оценки попытки (`{ bulls: number, cows: number }`), где `bulls` — количество точных совпадений (символ и позиция), а `cows` — количество частичных совпадений (символ есть в секрете, но на другой позиции).
- **`WinRecord` (Запись о победе):** Структура для сохранения и ранжирования результатов в таблице лидеров:
  - `attempts: number` — количество попыток, затраченных на победу.
  - `duration: number` — длительность игры в секундах.
  - `base: Base` — система счисления сыгранного раунда.
  - `length: number` — длина загаданного слова.

### Схема работы с `localStorage`

Для сохранения истории побед между сессиями используется обертка `storage` над браузерным `localStorage` с асинхронным интерфейсом (`Promise`):

1. **Ключ хранения:** `'wins'`.
2. **Формат данных:** Сериализованный JSON-массив объектов `WinRecord[]` (например: `[{"score": 4, "time": 20, "base": "dec", "length": 4}]`).
3. **Инициализация (чтение):** При загрузке приложения вызывается `storage.getItem('wins')`. Полученные данные проверяются через `Array.isArray(data)` — при отсутствии записи или повреждении данных инициализируется пустой массив `[]`.
4. **Сохранение (запись):** При победе (`status === 'won'`) формируется новый объект `WinRecord`, объединяется с текущим списком через `[...historyCache, recordItem]` и сохраняется через `storage.setItem<WinRecord[]>('wins', newState.winRecords)`.
5. **Ранжирование при отображении:** Перед выводом в DOM-таблицу записи сортируются по скорректированному коэффициенту сложности $\text{attempts} \times \frac{1}{\log_2(P(\text{base}, \text{length}))}$ с мемоизацией коэффициентов, а при равенстве баллов — по возрастанию `time`.

## Принципы чистого кода (Clean Code)

В проекте применены следующие ключевые принципы написания чистого кода:

### 1. Избегание магических чисел (Magic Numbers)

Все пороговые значения вынесены в именованные глобальные константы в начале файла:

- `MIN_SECRET_LENGTH = 2`
- `MAX_SECRET_LENGTH = 6`
- `BINARY_MAX_LENGTH = 2`
  Это централизует конфигурацию игры и исключает появление «необъяснимых» цифр в условиях валидации функций `countPossibleSecrets`, `generateSecret` и `isValidGuess`.

### 2. Использование функций высшего порядка по существу задачи

Вместо императивных ручных циклов со счетчиками (`for`, `while`) используются декларативные методы массивов:

- **`reduce`** в `evaluateGuess` — идеально подходит по смыслу для трансформации коллекции (массива символов) в единый агрегированный объект результата `{ bulls, cows }`.
- **`every`** в `isValidGuess` — семантически выражает предикат проверки всей коллекции и изящно реализует паттерн _Fail-Fast_ (прерывание вычислений «при первой лжи») штатными средствами языка.
- **`filter`** в `generateSecret` — декларативно отсекает использованные символы алфавита.

### 3. Использование понятных и содержательных имен (Meaningful Names)

Переменные переименованы таким образом, чтобы их названия полностью отражали их доменную суть, избавляя код от абстрактных технических терминов вроде `result`:

- `totalCombinations` (вместо `result`) — явно указывает на вычисленное количество комбинаций секретов.
- `uniqueCharsSecret` (вместо `result`) — подчеркивает, что строка формируется из набора уникальных символов.

### 4. Единая ответственность (Single Responsibility Principle)

Каждая функция сфокусирована строго на одной задаче. `evaluateGuess` занимается исключительно подсчетом быков и коров, валидация входных данных полностью инкапсулирована в функции `isValidGuess`, а генерация — в `generateSecret`.

### 5. Принцип Don't Repeat Yourself (DRY)

Повторяющаяся логика проверки символов алфавита вынесена в фабрику-замыкание `createDigitValidator(base)`, что позволяет использовать сгенерированный валидатор в методе `every` без дублирования операций приведения к регистру.
